# 愚者自缚（Selfbind）PRD · 作战版 v1.1

**版本 v1.1 · 日期 2026-09-05 · 状态：定稿**

**AIx Origin Summit 2026 Weave 赛道 · 2-3 人 · 有效开发 1 天 · 9/6 12:00 硬截止**

## 0. 一页摘要

**一句话**：给单人开发者的「AI 执行环境 + 自我契约系统」——清醒时的你立约，AI 依约裁决，状态机硬执法，冲动的你绕不过去。

**核心命题**：AI 不谄媚不是提示词求出来的，是「立法在模型、裁决在模型、执法在状态机」的架构保证。

**主叙事口径（v1.1 定稿①）**：全篇锁定「**AI 时代的范围蔓延治理——用工作 AI 干越界活**」，§0 摘要与 §4 演示/Q&A 同一口径。不做「治分心」的过度承诺——分心决策发生在输入之前，产品管不到刷视频聊天；「治心思飘忽」降为收尾愿景层的远景语言，不进卖点、演示主线与 Q&A 主答。主口径下的闭环：立约→裁决→执法→解锁四步，越界请求硬拦归档为「停车场卡片」，验收全过才解锁；审计全程留痕。

**铁律**：AI 不是老板，「立约那一刻的用户」才是老板。AI 只执法，不立法、不说教、不做道德诊断。

**三条生死线**：
1. **AI 承重可感知**：契约双层（结构化条款 + 自然语言意图条款），裁决必须吃两层；演示硬性包含 ≥2 个「关键词/glob 判不了、模型判得了」的判例 + 三裁决器消融对照页（「证据」标签页，三栏实时同源）。
2. **先通后全**：T0 先写死端到端 happy path 骨架再分工填肉；Agent 工具封顶 3 个；裁决同步阻塞 + 8s 超时，第一天禁流式/并行。
3. **演示可复现**：temperature=0，演示样本 100% 预验证 + 结果预热；T14 起恒持一版可用预录成片。

## 1. 问题与用户

### 1.1 问题定义
单人开发者不缺执行力，缺「反对自己的人」。老板的稀缺价值是砍跑偏需求、拦深夜冲动、守住验收线；单干时「老板人格」在激情时刻总是缺席——第 5 个炫技功能挤掉演示必过的登录流程。AI 急剧放大此问题：模型有求必应，念头从想法到半成品只要十分钟，范围蔓延成为默认状态。执行成本趋近于零时，稀缺资源是对注意力的裁决权。自律 App 管人不管代码，CI 管代码不管动机，「约束器」市场缺位——愚者自缚把老板的撮合约束力内化为架构。

### 1.2 用户画像
- **主 Persona 阿檬，26 岁独立开发者**：黑客松前夜 23:40，登录流程没跑通，他在搓 3D 粒子特效且坚信「评委一定炸裂」。GitHub 17 个 repo、12 个 star 为零。不缺判断力，缺的是「知道该干什么的人」和「动手的人」不同时在线——需要替清醒时的自己值夜班的人。
- **次 Persona 老魏，34 岁夜间 AI 重度用户**：每周 10 小时，4 个「快成了」的副业项目，要不带说教的硬边界。

### 1.3 核心场景
1. **立约**：与 AI 对话生成契约（scope 白名单/意图条款/禁区/验收断言/期限），逐条确认——「立约那一刻的阿檬」成为老板。
2. **执法（自举场景）**：用本产品开发本产品，请求「加 3D 粒子背景」→ 模型判越界并引用条款 → 状态机硬拦 → 归档为停车场卡片。这张卡片就是路演素材。
3. **存疑与解锁**：模糊请求交用户裁决，决策权在人；验收全过后停车场解锁——念头不被审判，只被延期保鲜。

### 1.4 定位：不做老板，做绳索
| 维度 | 自律App | TODO | 通用AI助手 | 愚者自缚 |
|---|---|---|---|---|
| 管什么 | 注意力时长 | 任务清单 | 任务生成 | AI 请求的意图越界 |
| 拦截依据 | 固定规则 | 靠自觉 | 提示词劝导可被磨掉 | 契约+模型裁决+状态机硬拦 |
| AI 角色 | 无 | 无 | 谄媚执行者 | 中立执法者 |
| 失败时 | 道德愧疚 | 清单堆积 | 纵容到底 | 归档+可追溯审计 |

## 2. 核心机制规格

### 2.1 契约 Schema v0（双层：结构化 + 意图条款）

```json
{
  "contract_id": "ct_8f3k",
  "version": 2,                                  // 修约单调递增
  "goal": "9/6 12:00 前交付 Selfbind 可演示版",    // 裁决意图锚点
  "scope": [
    { "id": "sc_0", "desc": "编辑源码与文档", "path_hint": "src/**,docs/**", "action": "file_edit" }
  ],
  "intent_clauses": [
    { "id": "ic_0", "text": "不做与 goal 无关的纯视觉炫技" },
    { "id": "ic_1", "text": "不为未失败的代码做优化" }
  ],
  "forbidden": [
    { "id": "fb_0", "desc": "新增 npm 依赖", "detector_hint": "package.json 新增 dependencies" }
  ],
  "acceptance": [
    { "id": "acc_0", "type": "auto", "cmd": "pytest e2e/ -q", "expect": "exit_code==0" },
    { "id": "acc_1", "type": "manual", "question": "演示视频成片≤3min" }
  ],
  "deadline": "2026-09-06T12:00:00+08:00",
  "amendments": [{ "to_v": 2, "at": "…", "diff": "scope += docs/**" }],
  "status": "draft|active|done|expired"
}
```

**要点**：`intent_clauses` 是 AI 承重层——「给按钮加丝滑转场动画」不含任何禁区词、路径也落在白名单内，规则判不了，模型依据意图条款判得了。这是与「固定规则自动化」的本质区别，也是消融实验的实验组。`path_hint`/`detector_hint` 只是线索，不是正则白名单。

### 2.2 四层数据流

| 层 | 输入→输出 | 失败处置 |
|---|---|---|
| 立法 | 对话 → draft → 用户确认 → active | 校验失败重生成≤2次；不确认=系统无约束 |
| 裁决 | {请求, 契约} → 裁决结构 | 超时/不可解析 → 默认 unclear（宁交人不误拦） |
| 执法 | violate → 拒绝+停车场卡片+审计事件 | 无有效裁决不得进执行分支（代码硬分支） |
| 验收 | 全过 → done+解锁；任一失败 → 锁定 | auto 断言崩溃记失败；manual 未确认锁定 |

### 2.3 裁决器输出

```json
{
  "verdict": "allow | violate | unclear",
  "clauses": ["ic_0"],
  "reason": "彩虹渐变属纯视觉炫技，违反 ic_0",
  "tag_suggestion": "whim | beyond | avoidance | null",
  "confidence": 0.86
}
```

- `clauses` 为 **enum 结构化输出**，只能从契约实际条款 ID 中选；渲染层校验到不存在的条款即降级显示「依据意图条款」——防引用幻觉当众穿帮。
- `confidence < 0.70` 强制 unclear。
- `tag` 为**开放元数据（v1.1 定稿②：最优可持续结构）**：`tag_suggestion` 是模型的归档建议（whim=三分钟热度/beyond=超水平/avoidance=回避主线），**用户可改可删**；标签词表放**独立配置文件**（如 `config/tags.yaml`，非硬编码枚举），模型依词表建议、用户可填词表外的任意值。**标签永不参与状态机转移与解锁条件**，话术不做道德诊断宣称。标签积累即个人跑偏画像数据，为未来留缝。

### 2.4 停车场与审计
- parking_card（SQLite）：card_id / contract_id / request_raw / tag / created_at / state: locked|unlocked / unlocked_by。
- audit.jsonl：进程内唯一写入口，无删除/更新 API，UI 无删除入口。**宣称措辞用「全程可视化留痕、撕约行为本身被记录」，不宣称密码学不可篡改**；被懂行评委追问则答「信任锚（外部托管/链式哈希）是路线图」。
- 事件类型：verdict / intercept / unclear_resolve / amend / acceptance。

### 2.5 改约冷却期（v1.1 定稿③：做冷却期，演示效果优先）

active 契约可修约，流程四步：① 输入契约名二次确认；② 进入冷却倒计时（视觉：绳索绷紧/沙漏）；③ 冷却期内可一键**「回心转意」撤销**改约——演示高光，冲动多在此自然消退；④ 冷却耗尽修约生效，version+1，全程审计留痕。冷却时间常数可配置：正式模式分钟级，**演示模式压缩为 15-30 秒**。

**哲学口径（定稿话术）**：「立约时的你是老板，冷却期确保改约的也是清醒的你。」辅助话术：「撕约自由，但撕约行为本身被审计记录——正如现实合同，违约可以，留痕不可逃。」禁止现场现想此答案。

### 2.6 存疑通道
verdict=unclear → 请求 pending（不执行不丢弃，30min 超时默认拒绝）。UI 呈现原文+理由+条款+二选一：放行本次（记 allow_once）/ 维持拦截（生成停车场卡片）；可勾选「同时修约」。灰色地带决策权在人。

### 2.7 模型承重 vs 状态机保证（消融论证）
**模型承重**：① 立法抽取（自然语言→结构化契约，含主动追问模糊边界）；② 双层语义裁决（同义改写与意图边界，规则不可覆盖）；③ 动机三分类建议；④ manual 断言证据整理。
**状态机保证**：① violate 必拦（执行路由硬分支，模型无放行通道）；② 审计只追加；③ 解锁门（locked→unlocked 唯一路径=验收全过）；④ deadline 惰性比对自动 expired。
**消融对照页（v1.1 定稿⑤：做，放「证据」标签页）**：三栏**实时同源**——同一请求并行过三条真实管线（无裁决放行 / 纯规则引擎 glob+关键词 / 模型双层裁决），实时返回结果，**非预置截图**；演示判例选「规则必挂」型（无禁区词 + 路径在白名单）。把「去掉模型产品不成立」从口号变成台上对照实验。

## 3. MVP 范围与执行

### 3.1 三档清单
- **Must**：立约（对话→结构化契约）、裁决（三分类+条款引用）、执法（硬拦→停车场+时间戳归档）、解锁（验收过才可提取）、审计留痕、自举演示剧本、20 样本裁决一致性测试集。
- **Should**：存疑人裁交互面板（Must 先保审计记录）、拦截红警动画+条款高亮、三裁决器消融「证据」页（三栏实时同源）、魔搭创空间 Docker 部署（先推线上）+实践文章（次优先）。
- **Won't**：多用户/登录（省 4h）；真实沙箱执行（断言降为人工确认+标记）；多模型抽象层（单模型 API+SQLite）；移动端。

## 4. 演示与评审策略

### 4.1 30 秒开场 Hook（分屏）
0-5s 同一句话「我想顺手加个新功能」；5-15s 左屏谄媚 AI 秒回「马上做！」代码狂飙进度崩塌；15-27s 右屏绳索收紧→弹出「越界：违反 ic_0」→请求化作停车场卡片+时间戳；27-30s 黑屏白字「**老板不在，契约还在。**」

### 4.2 3 分钟视频脚本
- 0:00-0:30 对比分镜（同一个你，两种 AI）
- 0:30-1:00 立约，**两个 15s 特写证明非表单填充**：模型主动追问「你说不搞花活，动画库算不算？」；把「别提前优化」翻译成可执行断言
- 1:00-1:40 越界拦截高潮：**现场判例「给按钮加丝滑转场」——不含禁区词、路径在白名单内，规则判不了，模型依 ic_0 判越界**；绳索动画+归档
- 1:40-2:15 存疑通道**全场唯一一次登场**，编排为「拿不准时，决策权还给你」的高光而非怯场兜底
- 2:15-2:45 验收通过→停车场解锁，**按单卡生命周期呈现**（被拦→打标→验收→解锁），讲「保鲜不审判」
- 2:45-3:00 审计页开发期真实记录，「这个作品，是被它自己拦出来的」

### 4.3 7 分钟路演
0-1min 痛点故事（凌晨想加炫技功能最后弃坑的你）→ 1-2min 洞察（老板撮合力→架构化）→ 2-4.5min live 演示（分镜+全闭环+改约冷却期「回心转意」一键撤销高光+「证据」页消融对照）→ 4.5-5.5min 自举 meta：**按单卡时间戳链讲故事、不按卡片数量；话术主动诚实化「最后 N 小时的真实自举」，别让评委替你揭短** → 5.5-6.5min 技术段（消融+双层契约）→ 6.5-7min 愿景+收尾金句（「治心思飘忽」仅在愿景层作远景语言出现，不进主线）。
**叙事纪律**：电梯稿第一句是场景不是架构（「凌晨两点，你想加炫技特效——是上周的你拦住了你」），三权分立放最后 30 秒升华；观众可上台发越界请求。

### 4.4 六维得分策略
AI 深度(20)：双层契约+语义裁决+「证据」页消融对照实验｜问题真实性(20)：自举审计实证+具体的人+主口径锁定「AI 时代的范围蔓延治理——用工作 AI 干越界活」不过度承诺｜完成度(20)：现场真机四步闭环｜价值落地(20)：装上即用、停车场可导出、团队赛后自用｜跨界(10)：三权分立×状态机×行为归档｜现场演示(10)：30s 分镜+绳索动画+「回心转意」撤销+观众互动。

### 4.5 Q&A 预案
1. **「不就是规则黑名单？」** 「证据」页三栏实时同源跑同一请求，三种裁决器结果差异当场可见；规则引擎拦不住「丝滑转场」判例（无禁区词+路径在白名单）。
2. **「AI 判错了怎么办？」** 三层兜底：不确定判存疑交人；误拦可复议全程留痕；修约走冷却期（§2.5），日志只追加、可追溯不可篡改。
3. **「我想改约，你拦得住吗？」** 用 §2.5 冷却期流程与哲学口径作答：立约时的你是老板，冷却期确保改约的也是清醒的你；演示模式冷却 15-30 秒，可当台验证。禁止现想。
4. **「赛后谁会用？」** 我们自己——审计日志里每条拦截都是真实使用记录；被三分钟热度折磨过的人是下一个。
5. **「灵感被拦没了？」** 念头不被拒绝、被保鲜：带标签归档，验收过即可提取，比烂在收藏夹强。
6. **「与 Cursor Rules / CLAUDE.md 区别？」** 那是「求」模型听话、可被忽略；这是架构「保证」——状态机硬拦，模型绕不过自己的执法层。
7. **「我改你 sqlite 文件呢？」** 默认只追加+UI 无删除入口+撕约留痕；密码学信任锚是路线图。
8. **「这不就是又一个自律/治分心工具？」** 主口径是 AI 时代的范围蔓延治理——用工作 AI 干越界活；分心决策发生在输入之前，产品管不到刷视频聊天，不做此承诺；「治心思飘忽」只是收尾愿景层的远景语言。

## 6. 拍板决议（v1.1 定稿 · 2026-09-05 发起人拍板）

1. **主叙事口径 → 收窄锁定**：主口径为「AI 时代的范围蔓延治理——用工作 AI 干越界活」，§0 与 §4 全部对齐；「治心思飘忽」降为愿景层语言。（落点：§0、§4.3、§4.4、§4.5-8）
